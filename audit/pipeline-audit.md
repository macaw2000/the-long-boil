# Pipeline audit: The Long Boil content crew

Jeremy Rule · Assignment 7 · 22 November 2026 · Costs are at Claude API list prices from each run's `crew/runs/<run>/usage.json`. The runs were billed to a Claude plan, so no money changed hands.

**What it produces.** One storylet per brief: a choice-driven scene as `storylet/1` JSON, plus its row in the provenance register. The Scrivener agent drafts it, the game's 12 validators check it, and the Inspector agent reviews voice, lore and reveal timing. Code writes the register row. With `--apply`, the files go straight into `content/`, the engine loads them at startup, and a push to `main` deploys to AWS. Four scenes in the live game came from this crew: `act1.lowvents.shovel_rack` (the run in the video), `act1.rustmoor.silk_line`, `act1.lowvents.wet_coats` and `act1.sprocket_row.mending_basket`.

**What it cost.** The submitted run (22 November, 14:39) cost **$0.83** for one shipped storylet over two rounds and 3 minutes 50 seconds. The Inspector failed round 1 because two lines had characters knocking on metal, which breaks Act I's "nothing knocking" rule, and the Scrivener fixed both.

The **most expensive step is the Inspector's review**, and output (thinking included) is 58% of the run's cost. **It is sustainable for a solo developer:** at $0.83 a scene, Act I's 52 storylets would cost about $43, and on a Claude plan the extra cost of a run is zero. For scale, building the whole game with Claude Code came to $906 at API prices over a month, and hosting costs about $61 a month on AWS (`audit/`).

**Manual steps that remain.**
1. *I write the brief.* Eliminating it: have the Assayer, which already plays the build through a simulator, turn the gaps it finds into briefs.
2. *I commit and push after `--apply`.* Eliminating it: have `--apply` commit to a branch and open a pull request, so merging is the approval.
3. *I approve after playing the build.* This one stays on purpose: no agent may approve content.
4. *Sprites are generated by hand in Gemini,* then cut by `scripts/art/`. Eliminating it: call Gemini's image API from the pipeline, with the prompts already kept in `docs/art-requests.md`.

**(a) An architectural decision I would change.** Each agent runs as a separate one-shot `claude -p` call that resends about 15,000 tokens of canon, and Claude Code writes that context to a 1-hour cache at twice the input price. In the submitted run, cache writes were $0.34 of $0.83 (41%), and a cache is only read again if the same agent's prompt is reused within the hour. **Alternative:** call the API directly and put the shared canon first in every agent's system prompt as one cached block, with the agent's role after it. The canon would then be written once per run and read by every later call at $0.20 per million tokens instead of $8. By this run's numbers, that saves about $0.25 a run, roughly 30%.

**(b) A cost reduction I made, with before and after.** The register row was written by a Registrar agent (Opus 5.5, low effort). In the recorded "before" run (13:52) it made two attempts, 11,002 input and 2,926 output tokens, for **$0.127, 20% of that run.** Both attempts failed the register's schema, so nothing shipped. Every field in that row is a fact the orchestrator already holds, so on 22 November I replaced the agent with code (`register_row` in `crew/crew.py`, commit `aff4fad`). **After: 0 tokens, $0.00,** and the row passed the provenance check on the first try. The old agent remains behind `--registrar-agent`.
